# Add consumption to an existing open account

The sale cart now offers **Agregar a cuenta existente** above **Facturar** (green banknote icon), followed by full gray **Seguir agregando** and red **Descartar venta** buttons on phone. The existing desktop cart also offers direct account attachment and billing. A selected account can later be settled using **Facturar cuenta**, reusing the existing collection form.

The account picker refreshes authorized state, shows only customers with a positive USD balance and supports search. Each row shows the exact account name, current pending amount, this consumption and resulting balance. Names are display labels: selection posts the stable customer UUID, so equal or differently entered names cannot silently create/choose another account. Tapping the row immediately records the products as a new credit sale on that account; the picker explains this before selection. Cancel keeps the cart. If there are no open accounts it offers a clear return to the normal billing flow.

`database/fridge_existing_account.sql` backs up and replaces the existing authorized command and state functions. The global operation lock, current account lock, stock/price checks and idempotent operation ledger are reused. The server requires an existing account with a positive current balance and rejects collections on this path. It derives project/staff/courtesy identity and pricing mode from recorded data, ignoring posted names or pricing overrides. Existing courtesy accounts retain purchase-cost pricing and zero percentages; normal accounts retain their standard sheet. The original monetary/ingredient snapshots and all earlier sales/reports remain unchanged. New sales reduce finished-product stock immediately and create debt, without cash received or duplicate account identities. Component inventory consumption remains disabled.

State adds the recorded pricing basis to the existing customer projection so the picker shows accurate cost-only amounts. No tables, columns, access roles or table grants are added. `database/fridge_existing_account_rollback.sql` restores previous function definitions while retaining recorded debt, movements, receipts and histories; the former command rejects cached `existing` requests. Revert frontend assets with rollback.
