# Regreso del paso 12 al 11

Se reutilizan `candidate-route-back`, la flecha izquierda, el diálogo y el flujo de confirmación existentes. No se añade CSS. El control conserva el nombre accesible «Regresar a la etapa anterior».

La etapa visible no es el estado laboral. Para una persona ya contratada se registra un evento de navegación en el historial; no se cambia `hired`, ni se revoca la contratación o el acceso. El paso 11 reabierto permite continuar al 12 con la notificación y documentación existentes, sin reenviar mensajes ni regenerar contratos. El retroceso anterior de candidatos todavía en prueba conserva su implementación.

La función privada exige propietario autenticado, bloquea la candidatura durante el cambio, valida contratación vigente y ausencia de baja, rechaza retrocesos repetidos y exige reconocimiento de cuenta activa. El aviso usa el diálogo existente. Si la cuenta se activa mientras el diálogo está abierto sin aviso, el servidor rechaza el retroceso. El paso 13 conserva su propio retroceso al 12.
