# Phone navigation and live sale cart

At viewport widths up to 650 CSS pixels, Nevera uses the approved four-button dock: Resumen, Venta, Cuenta, Más. Más opens a native modal with the three other Nevera views (Existencias, Carta menú, Cuadre) and the authenticated global navigation. Tablet and desktop retain the previous navigation and inline cart.

The outer dashboard hides its global dock only after the current, same-origin Nevera iframe reports that its phone UI is ready. The iframe then occupies the full available viewport. The handshake reverses on sign-out, leaving Nevera or widening the viewport. Child and parent messages validate origin and the current window source. Global entries are derived from existing visible authorized sidebar links; action requests revalidate the live links. Account opens the existing account controls. No permissions are added. A standalone Nevera page provides a safe return to Inicio for global navigation.

While selling, the fixed cart summary shows the selected unit count and USD total above the single dock. Product cards show the quantity already selected. Ver venta opens a bottom sheet with private thumbnails, prices, remove actions and quantity controls; the sheet and original cart share the existing in-memory selection. Search/category filters and local tab changes preserve that selection. Closing the sheet restores the catalog's scroll position. Switching views scrolls to the new view's top. Escape, close button, background tap, Seguir agregando and viewport changes close the sheet and restore background scrolling. Facturar closes the sheet and opens the existing sale confirmation. Agregar a cuenta existente opens a searchable picker and attaches the consumption by account ID as pending credit; see FRIDGE-EXISTING-ACCOUNTS.md.

Adding, removing and editing cart quantities make no ledger writes. Server-side stock, cost-only courtesy, actual collection, idempotency and reconciliation behavior remain unchanged. Existing recovery blocks prevent new modal operations during uncertain pending commands. A successful sale clears both displays. Descartar venta below Seguir agregando asks for confirmation, then clears the local selection, counters and badges and returns to the catalog; cancelling preserves the selection. It makes no ledger write and is blocked while a command remains unconfirmed. Parent navigation departure preserves existing unsaved-work/selected-product confirmation; opening account controls retains the cart.

Stylesheets parse in JSDOM. These checks do not constitute a physical phone/browser review. No real products, sales, collections, accounts or reports are modified by verification. No database migration is required.

Embedded legacy reconciliation pages may ask their verified parent for the same route on initial load when no unconfirmed reconciliation operation exists.
